# Kiosque et catégories 0.9.1

Extension du main d7652f4, incluant le sélecteur multi thèmes et les correctifs caméra/impression précédents. Les captures de catégories utilisent exclusivement des thèmes de test « Citron » et « Velours » pour vérifier l'ordre des sections et les sélections transversales ; elles ne définissent pas les sept tables réelles et n'appellent aucun modèle. La capture vingt thèmes vérifie le défilement et les textes longs. Les contrôles restent dans le viewport et le pied est fixe à 1280×800 et 960×700.

Le parcours UI couvre code enregistré, mauvais code, appui court/annulé, maintien souris/tactile de trois secondes, absence de code, redémarrage en plein écran, refus fermeture/F11/Échap/réduction, masquage et refus du bouton fichiers pendant le verrouillage. Le mode normal conserve l'accès aux fichiers après sortie par les réglages. La capture, l'impression simulée, le QR précoce et la génération de la séance précédente restent couverts.

`native-kiosk.json` consigne la vérification d'une vraie fenêtre Windows avec un profil séparé sans connexion cloud : 3840×1080, sans bordure ni barre des tâches, Réglages caché et focus conservé après F11, Échap, Alt+F4, Alt+Tab et Ctrl+Maj+Échap. Aucune touche Windows ni Ctrl+Alt+Suppr n'a été injecté. Les touches Windows sont couvertes par les tests de politique. Le filtre natif a été installé et retiré dans la suite Windows. Aucun secret ni capture de bureau personnelle n'est livré ici.

`kiosk-schema.json` vérifie les XML Windows 10, Windows 11 et un chemin avec esperluette contre six schémas Assigned Access officiels Microsoft. Les politiques n'ont pas été appliquées sur ce PC. Le verrouillage OS du compte standard de la borne, les gestes système et le matériel Canon/DNP restent des gates de salle.

`publication-audit.json` ne contient que les compteurs de l'audit. Gitleaks analyse tous les refs Git ; un second passage compare le code de connexion actif en mémoire à tous les blobs et aux fichiers extraits, puis cherche les liens privés de galerie/viewer et de photos signées. Les pièces jointes des releases, discussions et 64 journaux Actions sont analysés avec valeurs masquées. Aucun secret détecté. Les exports bruts et le vrai code ne sont jamais versionnés. La visibilité GitHub n'est pas changée par cet audit. Le script CI audit-secrets.ps1 empêche l'ajout ultérieur d'un secret reconnu dans l'historique ; il ne dispense pas de relire les fichiers et images avant publication.
